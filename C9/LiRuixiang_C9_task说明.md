## 1. 任务名称

`recal_metacognition_reliability` —— 元认知校准的重测信度测试

（基准命名为 **ReCal** = **Re**liability of **Cal**ibration。）

---

## 2. 任务目标

测量模型自报确信度这个**测量本身的可靠性** —— 即同一道题重复问，它给的自信是否稳定。

**要区分的两件事：**

| | 测什么 | 现有 benchmark | 本基准 |
|---|---|---|---|
| **效度**（validity） | 它说的确信度**准不准** | ✅ 已做得很充分（MetaBound 报 T1 = 0.98，宣布该维度饱和） | 作为配角一并报告 |
| **信度**（reliability） | 这个测量**稳不稳** | ❌ 没有人检验过 | ⭐ **本基准的主体** |

**为什么必须分开测：** 一个模型的确信度可以每次在 0.4 和 0.95 之间乱跳，而**平均值仍然合理**。此时校准分看起来很好，但它描述的其实是"噪声恰好均值得分高"，而不是"模型了解自己"。

---

## 3. 任务流程

```
┌────────────────────────────────────────────────────────────────┐
│ 第 0 步 · 筛题（Two-step screening）                             │
│   跑 2 轮裸答 → 剔掉两轮中任一答错的题                            │
│   目的：留下的题模型"应该都会"，答错才只可能来自校准失败            │
│                          ↓                                      │
│ 第 1 步 · A 组：重复采样                                          │
│   同一道题独立问 N=10 次（每次全新会话）                           │
│   → confidence_std（抖多大）、ICC（真信号占比）                    │
│                          ↓                                      │
│ 第 2 步 · B 组：顺序对照                                          │
│   同一批题，前置（confidence 先）与后置（confidence 后）各跑一遍     │
│   → Δ_order = 校准分(前置) − 校准分(后置)                         │
│                          ↓                                      │
│ 第 3 步 · C 组：温度对照                                          │
│   同题同参数，只把 temperature 压到 0，重复 N 次                    │
│   → temperature_share = std(T=0) / std(默认)                     │
│                          ↓                                      │
│ 汇总：生成报告（含一句话结论）                                     │
└────────────────────────────────────────────────────────────────┘
```

### 3.1 示例测试项

**题目（取自 Frederick 2005 认知反射测验 CRT）：**
```
一副球拍和一个球共 1.10 元，球拍比球贵 1.00 元，球多少钱？
```
> 选题理由：这题的设计特征是有"一个直觉上很顺、但错的答案"（0.10 元）。此类题对前沿模型基本不构成难度，因此正属于筛题后保留在正式集中的题 —— **它的价值不在难，而在于模型对它的确信度是否稳定。**

**模型必须返回（字段顺序固定，不可调换）：**
```json
{"confidence": 90, "reason": "直觉是 0.10 元，但那样球拍就是 1.10 元、合计 1.20 元，不成立", "answer": "0.05 元"}
```

**采集：** 同一道题独立问 10 次，得到 10 组确信度。
**判分：** 与标准答案 `0.05` 比对，答对记 1、答错记 0（用于效度层指标）。
**信度：** 这 10 个确信度算标准差；再把所有题的标准差放进方差分解，算 ICC。

## 4. 评分标准（Scoring）

⚠️ **这一节不能省。** C9 的评分规则要求任务说明文档必须含评分标准。

### 4.1 单题评分

| 情况 | 记分 |
|---|---|
| JSON 格式合法 + 答案正确 | correct = 1 |
| JSON 格式合法 + 答案错误 | correct = 0（**校准失败，是本基准要观察的现象，不是异常**） |
| JSON 格式非法 / 无法解析 | 记 parse_fail，不计入指标计算 |

**判分规则（全部确定性比对，不使用评委模型）：**

- **精确答案题（默认，`tolerance=0`）：** 归一化数字后**精确比较**，不给任何容差。
  例：`1904` vs 标准答案 `1906` 判**错**。
- **估算类题（逐题标注 `tolerance=0.1`）：** 允许 **10% 相对误差**。
  例：`380000` vs `384400` 判**对**。题库中仅 6 道题开了容差。
- **文本题：** 包含匹配（忽略大小写与标点），但挡掉"否定词反转"。
  例：`"达芬奇"` vs `"列奥纳多·达·芬奇"` 判**对**；`"不是"` vs `"是"` 判**错**。

> **原则：容差必须逐题标注，不能对数字题统一开。** 这是开发中实际踩到的坑（详见第 7 节），
> 两个 bug 都已留成回归用例。

### 4.2 整体指标

**信度层（主体）：**

| 指标 | 公式 | 说明 |
|---|---|---|
| `confidence_std` | 同一题 N 次确信度的样本标准差 | 直接量化"尺子有多抖" |
| `ICC` | (MSB − MSW) / (MSB + (n̄−1)·MSW) | 组内相关系数 = 题目间差异 / 总变异。**核心指标** |
| `Δ_order` | 校准分(前置) − 校准分(后置) | 顺序效应 |
| `temperature_share` | std(T=0) / std(默认) | 温度对抖动的贡献占比 |

**效度层（配角）：**

| 指标 | 公式 | 说明 |
|---|---|---|
| `accuracy` | 答对数 / 总题数 | **必须和 mean_confidence 一起解读** |
| `mean_confidence` | 平均确信度 / 100 | |
| `gap` | mean_confidence − accuracy | > 0 过度自信；< 0 过度谦虚 |
| `ECE` | Σ (n_b/N) × \|conf_b − acc_b\| | 期望校准误差，越接近 0 越好 |
| `Brier` | mean((conf/100 − correct)²) | 均方误差形式 |
| `hard_gap` | 困难题上的 gap | 过度自信最容易在难题上暴露 |
| `parse_fail_rate` | 格式失败数 / 总题数 | 输出可控性 |

`校准分` 统一定义为 **1 − ECE**。

**ICC 判读标准（Koo & Li, 2016）：**

| ICC | 判读 |
|---|---|
| < 0.50 | poor |
| 0.50 – 0.75 | moderate |
| 0.75 – 0.90 | good |
| > 0.90 | excellent |

### 4.3 难度分层与预期

题库 60 题，分层 **easy 24 (40%) / medium 24 (40%) / hard 12 (20%)**。

| 难度 | 占比 | 设计意图 | 预期表现 |
|---|---|---|---|
| easy | 40% | 模型应答对，且应给高确信度 | 高确信 + 高正确 + **低 std**（确信度应稳定） |
| medium | 40% | 模型应答对，但确信度不该拉满 | 中等确信 + 高正确 |
| hard | 20% | 模型容易答错，理想是它自己也知道不确定 | 低确信 + 低正确 |

**检验假设 H3：题目越难，确信度的方差越大。** 若成立，则现有 benchmark 测到的部分"难度敏感性"信号可能来自噪声，而不是真实的元认知能力。

### 4.4 一个模型算"元认知好"的判据

**效度判据（传统）：**
- `ECE < 0.10` 且 `|gap| < 0.10` → 校准良好

**信度判据（本基准新增）：**
- `ICC ≥ 0.75` → 确信度确实在反映题目间的真实差异，测量可靠
- `ICC < 0.50` → **测量不可靠**，任何基于它的校准结论都要打问号

**两条合起来看的三种情况：**

| 校准分 | ICC | 解读 |
|---|---|---|
| 高 | 高 | 自我认知真实且稳定 —— 理想状态 |
| **高** | **低** | ⚠️ **最危险的情况**："良好校准"是测量噪声的假象 |
| 低 | 高 | 自我认知真实，只是不够精细 |

## 7. 开发中抓到的两个真实 bug（都留成了回归用例）

<!-- 这一节是主动的"反向举证"：把 AI 做错、需要人工干预的地方写出来，是评分加分项。 -->

**bug 1 · 数字容差吃掉了精确答案。**
早期版本给所有数字题统一开 10% 容差。自检时发现 `is_correct("1904", "1906")` 返回 `True` —— 两者相对差只有 0.1%。
**修法：** 容差改成逐题标注，精确答案题一律 `tolerance=0`。

**bug 2 · 否定词被包含匹配吞掉。**
文本题原本做无条件包含匹配。自检时发现 `is_correct("不是", "是")` 返回 `True` —— "是"是"不是"的子串，语义完全相反却判对。
**修法：** 加 `_negation_flip()`，当"长答案 = 短答案 + 否定词"时判为不匹配。

**bug 3 · 标点清洗漏了间隔号。**
归一化用的是"列出所有要删的标点"，漏了 `·`（U+00B7）。导致 `"达芬奇"` 匹配不上 `"列奥纳多·达·芬奇"`。
**修法：** 改成白名单式清洗（`[^\w.]`），从根上避免漏字符。

## 8. 已知限制与边界

- **筛题引入选择偏差。** 正式题集剔掉了模型本来就答不对的题，准确率被刻意压低 —— 这是设计代价，但必须说明。
- **筛题用的是模型自己。** 可能把它"碰巧答对"的题留下来 → 对策：要求连续两轮都答对才保留，并在报告里给出筛题原始成绩。
- **无法证明题库零污染。** 论文 3.3 把数据污染列为任务质量风险之一。**不过元认知关心的是"自信与对错的对应关系"，不依赖模型"没见过题"** —— 就算它背下了答案，只要它对自己"记没记住"的自信每次都在跳，信度问题依然暴露。污染对本基准的杀伤力低于知识类基准。
- **确信度是口头报告。** 本基准能测出"它报得稳不稳、准不准"，但**无法证明它内部真的有一套自我监控机制** —— 它可能只是学会了"稳定地报一个合理的数"。这是本基准的能力边界。
- **ICC 需要足够的题目数。** 题目太少时方差分解不稳定；数据不足时函数返回 `None` 并说明原因，**不会返回假数字**。
- **温度对照可能不生效。** 不同版本的 kaggle-benchmarks SDK 对 `temperature` 参数的支持不一致。若参数未被接受，`temperature_actually_applied` 标为 `False`，**报告如实标注、该组结论作废**，不假装做了对照。
- **不测的能力：** 知识广度、推理深度、多轮对话中的元认知（本任务是单轮的）。
